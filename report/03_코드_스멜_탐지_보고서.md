# 코드 스멜 탐지 보고서

아래는 BMI 프로젝트 코드 스멜을 심각도 순으로 정리한 표입니다.

| 심각도 | 코드 스멜 | 위치 | 문제 | 영향 | 개선 방향 |
|---|---|---|---|---|---|
| Critical | God Class | `src/main/java/com/bestreviewer/SHealth.java` | `SHealth`가 파일 읽기, CSV 파싱, 누락 체중 보정, BMI 계산, 연령대별 통계, 결과 저장/조회까지 모두 담당 | 변경 이유가 너무 많아 유지보수와 테스트가 어려움 | `HealthRecordReader`, `WeightImputer`, `BmiCalculator`, `BmiStatistics` 등 책임별 클래스로 분리 |
| Critical | Long Method | `SHealth.calculateBmi()` | 20줄을 크게 초과하며 여러 처리 단계를 한 메서드에 포함 | 로직 흐름 파악이 어렵고, 작은 변경도 전체 메서드 회귀 위험을 만듦 | 파일 읽기, 체중 보정, BMI 계산, 통계 계산 메서드로 분리 |
| High | Magic Number | `SHealth.calculateBmi()`, `SHealth.getBmiRatio()` | `18.5`, `23`, `25`, `0.0`, `20`, `70`, `10`, `100`, `200`, `300`, `400`, `10000` 등이 하드코딩 | BMI 기준, 연령대, 타입 코드 의미가 불명확하고 정책 변경 시 수정 누락 가능 | BMI 기준/연령대/분류 코드를 상수 또는 enum으로 정의 |
| High | Duplicated Code | `SHealth.calculateBmi()` | `ages[i] >= a && ages[i] < a + 10` 조건이 여러 반복문에서 중복 | 연령대 기준 변경 시 여러 곳을 동시에 수정해야 함 | `isInAgeGroup(age, ageGroup)` 또는 `AgeGroup.contains()`로 추출 |
| High | Duplicated Code | `SHealth.calculateBmi()` | 연령대별 `underweight20`, `normalweight20`, `overweight20`, `obesity20` 저장 로직이 20대부터 70대까지 반복 | 연령대 추가/삭제 시 필드와 조건문을 대량 수정해야 함 | `Map<AgeGroup, BmiRatio>` 또는 `EnumMap` 기반 저장 구조로 변경 |
| High | Magic Number / Bug Risk | `SHealth.calculateBmi()` | 비만 조건이 `bmis[i] > 25`라서 BMI가 정확히 `25`인 경우 어떤 범주에도 포함되지 않음 | 통계 결과가 실제 요구사항과 다르게 계산될 수 있음 | 요구사항대로 `bmi >= 25`를 비만으로 분류하고 경계값 테스트 추가 |
| Medium | Long Method | `SHealth.getBmiRatio()` | 20줄 이상이며 `ageClass`, `type` 조합을 긴 `if-else`로 처리 | 조회 로직 확장성이 낮고 중복이 많음 | `getBmiRatio(AgeGroup, BmiCategory)` 형태로 enum 기반 조회 |
| Medium | Duplicated Code | `SHealthBMI.main()` | 20대부터 70대까지 거의 동일한 `printf` 호출 반복 | 출력 대상 연령대가 바뀌면 반복 수정 필요 | 연령대 배열을 순회하며 출력 |
| Medium | Magic Number | `SHealthBMI.main()` | `20`, `30`, `40`, `50`, `60`, `70`, `100`, `200`, `300`, `400` 직접 사용 | 호출 코드만 봐서는 타입 코드 의미를 알기 어려움 | `AgeGroup`, `BmiCategory` enum 사용 |
| Medium | God Class 징후 | `SHealth.java` | `ages`, `heights`, `weights`, `bmis` 병렬 배열과 24개 통계 필드를 직접 보유 | 데이터 구조가 도메인 개념을 표현하지 못하고 필드 폭증 발생 | `HealthRecord`, `BmiRatio`, `BmiStatisticsResult` 같은 도메인 객체 도입 |
| Low | Duplicated/Primitive Logic | `SHealth.split()` | CSV 파싱을 직접 구현 | CSV 포맷 변화, 빈 컬럼, 예외 케이스에 취약 | 최소한 파싱 검증 추가 또는 CSV 파서 책임 분리 |

가장 먼저 손볼 부분은 `SHealth.calculateBmi()`입니다. 현재 프로젝트의 핵심 계산 오류 가능성, God Class, Long Method, Magic Number, 중복 로직이 대부분 이 메서드에 집중되어 있습니다.
